# R3 lifecycle capacity probe

This probe measures artifact size and public CLI ingestion for a linear Git history generated by the tool. It writes source files and commits, calls `swift-debt analyze --lifecycle-artifact`, checks public `lifecycle inventory --format json`, then replays the final revision against the same artifact to verify byte-identical persistence. The script never constructs lifecycle JSON. The Snapshot and Finding axes can be run separately, as required by the R3 PRD.

## Fixture

| Snapshot | Source | Expected Finding state |
| --- | --- | --- |
| 1 | No debt | No Findings |
| 2 | One `try!` per requested Finding, in functions with at most 16 statements | Open |
| 3 | Remove all `try!` | Resolved |
| 4 through N | Unique comment change, still no debt | Resolved |

With `--findings 0`, all Snapshots contain clean source with a unique comment and no Findings. The 16-statement grouping for positive Finding counts stays below the built-in Long Function threshold. One repository and one Swift file keep the fixture focused on persistence rather than repository traversal. Every revision is a clean direct Git successor. The artifact and CLI outputs live outside the repository.

## Bounded pilots

Build the exact source revision first, then run these commands one at a time. Set `BIN` to that revision's release `swift-debt` executable. The output JSON records the script checkout commit and dirty state, script SHA-256, and binary SHA-256. A clean script checkout and a fresh build are needed for exact-head source provenance.

```sh
BIN="$(pwd)/.build/release/swift-debt"
python3 scripts/run_r3_capacity_probe.py --swift-debt "$BIN" --snapshots 10 --findings 100 --maximum-artifact-gib 0.25 --evidence /tmp/swiftdebt-r3-capacity-10x100.json
python3 scripts/run_r3_capacity_probe.py --swift-debt "$BIN" --snapshots 10 --findings 1000 --maximum-artifact-gib 1 --evidence /tmp/swiftdebt-r3-capacity-10x1000.json
python3 scripts/run_r3_capacity_probe.py --swift-debt "$BIN" --snapshots 100 --findings 100 --maximum-artifact-gib 0.25 --evidence /tmp/swiftdebt-r3-capacity-100x100.json
python3 scripts/run_r3_capacity_probe.py --swift-debt "$BIN" --snapshots 100 --findings 1000 --maximum-artifact-gib 1 --evidence /tmp/swiftdebt-r3-capacity-100x1000.json
shasum -a 256 /tmp/swiftdebt-r3-capacity-*.json
```

The default reserve is 8 GiB free in the temporary volume, with an artifact ceiling of 4 GiB, a one-hour total ceiling, and a five-minute limit for each command. The initial disk preflight requires reserve plus twice the configured artifact ceiling to allow atomic replacement; every subsequent snapshot requires reserve plus one artifact ceiling. Pilot commands set lower artifact ceilings. A capacity run checks free disk before every snapshot. It writes checkpoint evidence atomically and removes only its own temporary directory even on failure. `--keep-workdir` preserves the source repository and artifact for local diagnosis, so use it only when space permits. `--work-parent` selects a volume with enough free space. Evidence records the effective limits, checkpoint interval, and both Python source hashes. A previous `passed` value at the same output path is replaced with `running` before preflight; cleanup and the absolute time deadline must succeed before `passed` is written.

## Preliminary local observations

The following 2026-09-26 measurements used arm64 macOS 27.2, Apple Swift 6.4, and release binary SHA-256 beginning `b5ad60afa794af47`. They predate the runner's fail-closed repair and are diagnostic observations, not release proof. The three passing pilots used a dirty script checkout at `1fcd5e0eaaff`; the 1,000-Snapshot attempt used clean script commit `5a2801e50ff3` and failed its 1,200-second ceiling.

| Requested Snapshots | Requested Findings | Result | Last validated Snapshot | Artifact bytes | Total seconds |
| ---: | ---: | --- | ---: | ---: | ---: |
| 10 | 100 | Preliminary PASS | 10 | 1,219,207 | 3.71 |
| 10 | 1,000 | Preliminary PASS | 10 | 11,290,320 | 42.64 |
| 100 | 100 | Preliminary PASS | 100 | 2,130,278 | 141.20 |
| 1,000 | 0 | Failed time ceiling | 900 | 9,111,348 | 1,201.09 |

The 1,000-Snapshot attempt ingested 901 revisions and validated only the first 900 at checkpoints. It did not measure an accepted 1,000-Snapshot artifact. These figures expose scaling on the then-current artifact validator; a later engine optimization must be measured under its own exact binary and source identity.

Use the bounded pilots to set explicit ceilings for the two independent capacity axes. The target commands are:

```sh
python3 scripts/run_r3_capacity_probe.py --swift-debt "$BIN" --snapshots 1000 --findings 0 --maximum-artifact-gib 0.25 --checkpoint-every 100 --maximum-elapsed-seconds 14400 --evidence /tmp/swiftdebt-r3-capacity-1000x0.json
python3 scripts/run_r3_capacity_probe.py --swift-debt "$BIN" --snapshots 10 --findings 10000 --maximum-artifact-gib 0.5 --maximum-elapsed-seconds 14400 --evidence /tmp/swiftdebt-r3-capacity-10x10000.json
```

These targets are not release budgets or a claim of completion. The 1,000-Snapshot axis contains zero Findings; the 10,000-Finding axis contains ten Snapshots and removes debt at Snapshot 3. Neither proves the combined 1,000 by 10,000 case. These fixtures do not establish large-repository traversal, repeated 10,000-Finding reconciliation, Git introduction cache reuse, peak memory, inventory latency distributions, or small/medium/large release budgets required by [the R3 PRD](prd-r3.md#122-operational-metrics-to-baseline-before-release). The evidence JSON contains every ingestion wall time and artifact size, checkpoint inventory validation, artifact and Finding ID-set hashes, final Git revision, and replay time. Git commit dates are not fixed between runs, so independently generated repositories do not promise identical IDs or artifact hashes. Replay checks only the same artifact and jobs setting; it is not the fresh concurrent replay acceptance test AT-22. A failed or interrupted run must not be reported as a passing capacity result.
