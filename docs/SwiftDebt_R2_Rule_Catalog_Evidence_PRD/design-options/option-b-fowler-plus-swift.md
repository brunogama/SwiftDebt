# B: Fowler 24 plus explicitly sourced Swift extensions

Source: Martin Fowler, Refactoring, Second Edition, chapter 3 supplies the externally attributed 24-smell baseline already documented and typed on main. SwiftDebt-specific concurrency, SwiftUI, SwiftPM and CI examples are project-authored extension claims, not alleged entries in a missing 100-item list. Each extension requires its own concrete primary source or explicit project policy citation; absent sources remain Research/Unverified, not catalog-completeness success.

Contract: FR-1/SM-1 measure 24/24 Fowler source mappings plus 100% of **accepted, explicitly registered** extension claims, with separate counts and provenance kinds. Rule Identity remains stable and independent of old research numbers. Deprecate unresolved numeric researchItem in a new superseding ADR, not by silently editing accepted ADR 0001. Preserve R2 Evidence Contract, capability selectivity, Observation State, scopes, and typed reporting. Build a single canonical versioned Rule Catalog that exposes the existing Fowler entries and any evidence-backed Swift extensions, rather than silently creating two authoritative catalogs. Resolve Swift/YAML ownership before porting implementation, preserving existing report schema compatibility.

Upside: retains SwiftDebt's repository-aware differentiation, honest source taxonomy, and reusable future extension mechanism without fabricating 97 entries. Downside: more integration and provenance work than A; official docs may support capability facts but not the judgment that a pattern is debt, so project-authored policy provenance must be labeled as such. Tests must enforce partitioned completeness and compatibility.
