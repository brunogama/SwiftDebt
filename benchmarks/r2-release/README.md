# R2 release performance benchmark

This directory defines the reproducible performance slice for the deterministic
R2 repository rules. It exercises the real `swift-debt` CLI with similarity
disabled. It does not qualify the complete R2 release while cache, provider
telemetry, SQVector, and ANN scenarios remain unavailable.

---

## Files

| Path | Purpose |
|---|---|
| `manifest.v1.json` | Frozen source commits and engine versions, generated corpus snapshots, analysis-unit counts, configuration, environment, providers, scenarios, and budget policy. |
| `../../scripts/run_r2_release_benchmarks.py` | Release calibration entry point. |
| `../../scripts/r2_benchmark_*.py` | Corpus, process measurement, statistics, and scenario support. |
| `evidence/2026-09-25-m4-max/calibration.v1.json` | Final valid raw samples, aggregates, fixed proposed limits, and induced-regression proof. |
| `evidence/2026-09-25-m4-max/moderate-load-invalid.v1.json` | Retained fail-closed run collected during bounded background load. |
| `evidence/2026-09-25-m4-max/README.md` | Human-readable result and qualification gaps. |

The manifest is source configuration. The calibration JSON is generated by the
runner and should not be edited by hand.

---

## Measurement design

The runner creates deterministic Swift corpora at 16, 128, and 1,024 source
files. Each source contributes three Data Clumps analysis units and two Repeated
Switches units. Corpus hashes in the manifest make generator changes explicit.

Comparable R1 and R2 similarity-disabled commands run as paired samples. Their
order alternates within each pair. R2 repository-evidence commands use the same
corpora and write the independent repository sidecar. Every scenario uses five
unmeasured warmups and 30 measured fresh-process runs.

Raw report hashes and engine versions prove byte stability within each build.
The cross-version comparison canonicalizes JSON and removes only
`engineVersion`, whose expected R1/R2 difference is preserved separately in the
artifact. Any other report difference invalidates the paired scenario.

"Cold" here means a new process and a fresh derived-output directory for every
sample. The five warmups can leave filesystem pages resident. This benchmark
does not describe that state as cache-warm because the stacked source branch has
no persistent repository fact cache.

Wall time is measured around the complete process. Peak RSS comes from
`/usr/bin/time`. The runner also preserves each available `AnalysisProfile`
phase. Repository analysis has no dedicated profile phase in this source slice,
so its cost is present only in end-to-end wall time and process RSS.

Every measured command records the host one-minute load average immediately
before and after execution. On this 14-physical-core host, any scenario that
observes a value above 21 fails calibration. This permits a bounded moderate
background workload while rejecting samples collected during material host
oversubscription. The paired order, raw pair deltas, and median absolute
deviation preserve the remaining noise profile for review.

## Budgets and regression proof

The relative bounds preserve the existing SwiftDebt gate: 10 percent for wall
time and 15 percent for peak RSS. Each scenario gets an absolute short-stage
floor equal to the greater of 10 milliseconds and three median absolute
deviations. A stage below one second fails only when both its relative limit and
its absolute floor are exceeded.

The generated artifact records the effective fixed wall and RSS limits. Those
limits remain `proposed-for-review` until the calibration is approved. For each
scenario, the runner measures a deliberate workload increase consisting of two
complete sequential CLI analyses. The calibration is invalid unless that
increase fails the wall-time gate.

## Reproduce

Build exact reference and candidate source trees with the toolchain declared in
the manifest. The checked-in calibration builds both binaries independently
with this same command. Limit SwiftPM concurrency on shared hosts:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  swift build -c release --jobs 2
```

Then run the calibration from the candidate checkout:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
python3 scripts/run_r2_release_benchmarks.py \
  --manifest benchmarks/r2-release/manifest.v1.json \
  --reference-root /path/to/r1-reference \
  --reference-binary /path/to/r1-reference/.build/release/swift-debt \
  --candidate-root "$PWD" \
  --candidate-binary .build/release/swift-debt \
  --output benchmarks/r2-release/evidence/2026-09-25-m4-max/calibration.v1.json
```

The runner refuses a toolchain, OS, hardware, source commit, generated corpus,
or analysis-unit mismatch. It exits 2 when a measured scenario fails, the
induced regression passes unexpectedly, or the exhaustion proof is absent.

## Qualification state

| Requirement | State | Evidence or blocker |
|---|---|---|
| Similarity-disabled cold wall and RSS | Measured by this slice | Paired R1/R2 samples at all three scale points. |
| Raw samples, median, p95, and per-scenario floor | Measured by this slice | Generated calibration artifact. |
| Deterministic output | Measured by this slice | SHA-256 equality across measured outputs. |
| Comparison-budget exhaustion | Measured by this slice | Real CLI exit 2 and `comparison-budget-exceeded` sidecar issue. |
| Zero vector-index files in controlled roots | Measured by this slice | Every sample rejects unexpected output files and any change to the frozen source corpus. |
| Zero provider and index operations or files elsewhere | Open | The CLI exposes no operation counters or index-path telemetry. |
| Unchanged warm cache | Blocked | Persistent repository fact cache is absent from the stacked source branch. |
| Standard one-file edit | Blocked | Cache invalidation and re-embedding counters are absent. |
| SQVector exact-index latency, RSS, size, candidates | Blocked | The local adapter and static product revision are unpublished and outside this branch. |
| ANN recall and latency | Blocked | No ANN implementation is available. |

Index size and candidate count are not applicable to similarity-disabled
scenarios. They remain unavailable, rather than zero-filled, for the blocked
index scenarios.
